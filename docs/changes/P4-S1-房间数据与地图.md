## 1. 本步目标
5 个房间能进、能走、有墙有点位，`data:validate` 全过。

## 2. 改动文件

| 文件 | 类型 | 说明 |
|---|---|---|
| `web/src/data/rooms.json` | 修改 | 5 布局（40×24）+ 6 房间 + 关卡序列 + 经济参数，数值照 §9.5 |
| `web/scripts/gen-rooms.mjs` | 新增 | 布局生成器：代码画图 → 断言尺寸/符号/`P`或`B` 数量 → 写 JSON（避免手写 24×40 错位） |
| `web/src/systems/RoomSystem.ts` | 新增 | 布局解析、地板/墙体渲染、静态碰撞、P/S/C/$/B/G 点位提取 |

## 3. 契约与数据变动
- 契约：无改动。`LayoutDef` / `RoomDef` / `EconomyDef` / `RunMapDef` 全部按 §4.2 使用。
- 数据：新增 `rooms.json` 全量内容（§9.5 逐项对齐）。

## 4. 验收结果
- [x] `npm run data:validate` 通过（尺寸 40×24、符号合法、每个布局恰好 1 个 `P` 或 `B`）
- [x] 5 个布局的符号统计（生成器输出）：

```
layout_arena     P=1 B=0 S=4 C=1 $=0
layout_pillars   P=1 B=0 S=5 C=1 $=0
layout_cross     P=1 B=0 S=6 C=0 $=0
layout_ring      P=1 B=0 S=0 C=0 $=1
layout_hall      P=1 B=0 S=5 C=1 $=0（另含 1 个 B）
```

- [x] 墙体：`#` → 静态 body（`walls.create` + `refreshBody`），一次 collider 注册
- [x] 点位：`P` 出生点、`S` 刷怪点（按序轮询 + 抖动）、`C` 宝箱点、`$` 商店点、`B` Boss 点、`G` 装饰门
- [x] 兜底：布局没有 `S` 时用四角兜底并 `log.p4.warn`
- [ ] **人工试玩**：5 个布局走一圈、确认不卡角（本机无浏览器，见 DEV-004）
