## 3. 契约与数据变动
- 契约：签名全部保持不变。两处**实现侧扩展**（不影响 v1，建议 P1 记入下一版 ADR）：
  1. `circleArea(center, radiusPx, spec, faction = 'enemy')` —— 第 4 个可选参数只存在于实现类；
     Boss 砸地 / 前摇范围需要「打玩家」，而契约签名无法表达阵营。
  2. `damagePlayer(spec, sourcePos)` / `attachPlayerSprite(sprite)` —— 只存在于 `CombatSystem` 实现类，
     供同为 P2 的 `Enemy` / `PlayerService` 调用（不跨部分）。
  3. `IDamageable` 用**适配器对象**实现：Phaser `Sprite.getCenter(output?, includeParent?)` 与
     契约 `getCenter(): Vec2` 签名冲突，硬 override 会破坏类型推导。`Player.damageable` / `Enemy.damageable`
     各自暴露一个只读视图（id 用 getter，池化复用后 id 仍唯一）。
- 数据：无。

## 4. 验收结果
- [x] 管线顺序与 §6.3.1 逐步对应：存活 → 无敌（在 `applyDamage` 内）→ 暴击 → 处决 → 状态 → 扣血 → 击退（实体侧，只有它能读 `knockbackResist`）→ 吸血 → 连锁（仅 depth 0）→ 死亡爆炸 → 表现
- [x] 飘字与扣血同值：`dealt` 就是飘字数字，也是吸血基数
- [x] 暴击：`rand() < critChance` → `amount *= critMult`，飘字 24px 黄色带 `!`，额外震屏
- [x] 处决：`hpRatio <= executeBelow` → `amount *= executeMult ?? 2`，视作 crit 表现
- [x] 中毒 DoT：每 `DAMAGE_TICK_MS=500` 一跳，`dps × 0.5`；同元素**不叠加**（刷新时长、dps 取大）；DoT 不触发连锁/吸血
- [x] 连锁：`chain.count` 个最近目标、`damageMul` 递减、递归深度上限 1（`depth` 参数禁止再链）
- [x] 死亡爆炸：只在击杀且 `requiresStatus` 匹配时触发；伤害 = 目标 `maxHp × percentMaxHp`（通过结构化判型读 `getHp()`）
- [x] 对象池：弹道 120 / 飘字 24 / 火花 40 / 碎片 40 / 敌人 40；回收时 `disableBody + 重置 pierce/lifeMs + 清 tint`
- [x] 无绕路扣血：全仓库只有 `Player.applyDamage` / `Enemy.applyDamage` 两处 `hp - amount`
- [x] 伤害坐标快照：先记 `hitX/hitY` 再 `applyDamage`，避免敌人死亡回池被挪到 (-1000,-1000) 导致飘字飞到屏幕外（自测时发现并修的）
- [x] `tsc --noEmit` 0 error
- [ ] **人工试玩**：连续命中 10 次不糊、不闪屏，需人眼确认
- [ ] **120 弹道压测**：未实测帧率（见 DEV-004）
