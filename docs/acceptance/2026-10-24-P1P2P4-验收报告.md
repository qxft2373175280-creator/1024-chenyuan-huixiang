### 2.1 P1 验收发现（1 个 P0，已修复）

**[P0] 所有按钮只有左半边可点（`gfx/UiKit.ts` `createButton`）**

- 现象：点击「开始游戏 / 锻造台 / 静音」无反应；点按钮左半边有效、右半边无效、正中心因浮点误差失效。
- 根因：`container.setSize(w,h)` 后调 `setInteractive(new Rectangle(-w/2,-h/2,w,h))`。Phaser 在 `pointWithinHitArea` 里会先把局部坐标 `+displayOrigin (=w/2)` 再比命中区，等价于把命中区整体左移半个身位 → 实际只有左半边可点。
- 修复：改为 `setInteractive(new Rectangle(0, 0, w, h), Rectangle.Contains)`（已加注释说明）。
- 验证：修复后左/中/右三点均可进入 GameScene；`acc-p1-interact.mjs` 13 项全 PASS。
- 影响面：菜单、锻造台、奖励页、`?debug=assets` 的返回按钮；**P1 之前的「截图验收」看不到这类问题**，建议联调清单加一条「点按钮右半边」。
- 同类隐患：`ui/CardPicker.ts` 也写了居中矩形，但它的容器**没有** `setSize`（width=0 → displayOrigin=0），因此行为正确；已在代码里加注释提醒未来改 `setSize` 时要同步。

**[P2] 素材自检不校验「数据 id 是否有对应贴图」**

- `check-assets.mjs` 只列「用占位图的 key」，不把「数据里有 id 却没有贴图（且没生成占位）」判为失败。
- 影响：真素材接入阶段可能漏 key；已在 `待办事项.md` 登记为 DEV-019。

**[P3] 损坏存档只在读取阶段自愈，不回写 localStorage**

- 启动后 `localStorage` 仍是坏字符串，等下一次 `commit()` 才覆盖。行为符合「不因存档崩溃」的要求，属可接受实现；已在验收记录中说明，不登记为缺陷。

### 4A.1 第二轮修掉的 bug（BUG-003 / BUG-004）

**[BUG-003] 场景 SHUTDOWN 清理触碰已销毁的物理对象（P1 级，已修）**

- 现象：Boss 被击杀切结算、玩家死亡切结算时抛 `TypeError`（`removeCollider` / `body2.stop` / `world.timeScale` / `setVelocity`），
  后果是**结算页不出现、存档不写**（`active=[]`）。
- 根因：`Scene.SHUTDOWN` 时 physics 子系统可能已先销毁，但 4 处清理仍直接访问 `physics.world` / `body`。
- 修复：`ProjectileSystem.destroy()` / 池 release 回调 / `GameScene.cleanup()` / `Enemy.stopEverything()` 全部改空值兜底
  （外加 `onBossDefeated` 的慢动作还原）。
- 复测：`acc-flow.mjs`（Boss→结算→存档→刷新）与 `acc-death.mjs`（死亡→失败结算→材料→回菜单）均全绿。

**[BUG-004] 图鉴 `seen` 从来没被记录（P2/P4 级，已修）**

- 现象：打完一局后 `save.seen` 全是空数组，锻造台「已遭遇/未见过」永远停留在初始态，与 §13.4「刷新后 seen 仍在」不符。
- 根因：全项目只有 `ForgeScene` 读 `hasSeen`，**没有任何地方调用 `markSeen`**。
- 修复：装备武器（`Player.equip`）、刷怪（`EnemyService.spawn`）、装卡（`WeaponSystem.installCard`）、
  发卡（`DropSystem.cardOffers`）四处补记。
- 复测：全流程结束后 `save.seen` 计数 0 → 11。

  **[BUG-002] 敌人弹道命中玩家 → `Uncaught TypeError: target.isAlive is not a function`**

  - 现象：站在有喷吐者的房间不动，第一发敌弹命中即抛异常（异常被全局兜底捕获，画面继续但这一帧的伤害与回收流程被打断）。
  - 根因：`entities/Projectile.ts` 的「弹道 vs 玩家」overlap 回调把 **Arcade Sprite** 当成 `IDamageable` 传给 `CombatSystem.onEnemyProjectileHit`；玩家的 `IDamageable` 是 `Player.damageable` 适配器（Sprite 上没有 `isAlive/applyDamage`）。同一代码在 P2 原始副本与 P4 副本里都存在，**所以主工程合并后也带着这个雷**。
  - 修复：
    1. `ProjectileSystem.attach()` 增加 `resolvePlayer?: () => IDamageable | null`，敌弹命中时用注册过的 `IDamageable`；拿不到就跳过（宁可漏一次判定，也不让异常打断整帧）。
    2. `CombatSystem.attachProjectilesTo()` 传入 `() => this.playerTarget`。
    3. `onEnemyProjectileHit` / `onPlayerProjectileHit` 增加 `isAlive` 类型兜底，并按 id 换回注册表里的适配器。
  - 复测：`acc-enemy-shot.mjs` 第 3 房站桩 14s → **异常 0**，HUD 血量正常下降，日志多次「玩家受击」。
