# ADR-009 弹反系统：独立数据文件 + 事件表模块增量

- 日期：2026-10-25
- 状态：**已采纳**（PARRY-01 落地）
- 相关：`web/src/core/contracts.ts`（冻结，零改动）、`web/src/data/parry.json`、`web/src/core/parry-contracts.ts`

## 背景

新增「玩家弹反怪物蓄力攻击」需要两类契约外的东西：

1. **数据字段**：`EnemyDef.attack` 只有 `damage / cooldownMs / rangePx / windupMs / projectileSpeed / aoeRadiusPx`，没有蓄力总时长、弹反窗口、硬直、圈半径倍率等。
2. **事件**：`EventMap` 里没有 `enemy:windup_started` / `enemy:parry_window` / `enemy:parried` / `enemy:attack_released` / `enemy:recovery_started`。

工作令明确：先提数据结构变更方案，**不得破坏 `contracts.ts`**。

## 决策

### 1. 数据：新增独立文件 `web/src/data/parry.json`

- 不往 `enemies.json` 塞字段（会与冻结的 `EnemyDef` 类型脱节，`validate.ts` 也要改判定）。
- 新增 `web/src/core/parry-contracts.ts` 定义 `ParryFileDef`，`web/src/data/index.ts` 提供 `getParryConfig()`。
- 数值全部在 JSON；代码只保留纯视觉常量（颜色分段点、闪烁时长）。

### 2. 事件：TypeScript 模块增量（module augmentation）

```ts
declare module './contracts' {
  interface EventMap { /* 5 个新事件 */ }
}
```

写在 `parry-contracts.ts`，**不修改 `contracts.ts` 一个字节**。

## 理由

- **纯加法**：只新增 key，既有 key 的 payload 与语义不变，任何已签名的监听器都不受影响 → 不构成 §3.6 的破坏性改动，`CONTRACTS_VERSION` 保持 1。
- 比「升级到 v2 再改 contracts.ts」便宜得多，也不会让 4 个历史工作副本的契约版本对不上。
- 比「另起一套独立事件总线」安全：仍走同一个 `bus`，`offAll(ctx)` 的清理语义、监听器计数、调试工具全部复用。
- 数据放独立文件后，后续「哪些敌人可弹反、哪些武器能弹反」都变成改 JSON，不用碰契约。

## 代价 / 约束

- `EventMap` 的完整视图被拆到两个文件：读契约时要同时看 `parry-contracts.ts`。已在两份文档中互相引用。
- 模块增量必须有 import 才会被编译，因此 `ParrySystem` 必须 import `parry-contracts`（它确实要用这些 payload 类型）。
- 新增前缀 `PARRY-` 的待办编号（PARRY-001…007），已在 `待办事项.md` §二 登记。

## 备选方案（未采纳）

| 方案 | 未采纳原因 |
|---|---|
| 直接改 `contracts.ts` 加字段/事件并升到 v2 | 违反「不得破坏契约」的工作令；会让 4 份历史交付文档的契约版本失效 |
| 用 `any` 强转 key 调 `bus.emit('enemy:parried' as never, …)` | 丢类型安全，事件表从此不可枚举 |
| 弹反走一套独立 EventEmitter | 绕过 `offAll(ctx)` 清理，重开场景易泄漏（BUG-005 同源风险） |
