# ADR-002：契约层 + 服务注册表 + 事件总线（跨部分零实现依赖）

- **日期**：2026-10-24
- **状态**：已接受
- **决策人**：P1

## 背景

四个部分（P1 基座 / P2 战斗 / P3 构筑 / P4 关卡）要并行开发。若互相直接 import 实现文件，会天天冲突、互相阻塞。

## 可选方案

- 方案 A：契约接口 + 服务注册表 + 事件总线，跨部分只认类型
- 方案 B：直接互相 import 实现（简单，但强耦合、并行即冲突）
- 方案 C：引入第三方 DI 容器（多一个依赖，收益不明显）

## 决策

选 A。`src/core/contracts.ts` 为唯一契约；实现方用 `install*()` 注册服务；状态变化用事件广播。
唯一允许的跨部分 import 是 `GameScene` 调用 `installCombat` / `installBuild`。

## 理由

1. 并行开发时四人只对接类型，不互相等待；
2. 桩（stub）可以随时替换，联调成本低；
3. 事件驱动天然适合 HUD 与结算。

## 后果

- 正面：改动隔离、Review 简单、可独立测试。
- 负面：多一层取服务的间接性；已用「取不到就抛错 + 带排查提示」抵消。
