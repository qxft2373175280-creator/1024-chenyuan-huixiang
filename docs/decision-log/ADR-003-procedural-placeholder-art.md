# ADR-003：美术全程序化占位 + manifest 同名替换

- **日期**：2026-10-24
- **状态**：已接受
- **决策人**：P1

## 背景

比赛周期短，美术素材会晚于代码到位；不能让「没有素材」阻塞玩法开发，也不能让替换素材时改代码。

## 可选方案

- 方案 A：代码里程序化生成占位贴图（`TextureFactory`），美术到位后用同名 PNG 覆盖
- 方案 B：先等美术（阻塞开发）
- 方案 C：找免费素材包（风格难统一、授权不明）

## 决策

选 A。key 规则为「前缀 + 数据 id」；`BootScene` 先按 `public/assets/manifest.json` 加载真图，缺失的 key 再由 `TextureFactory` 生成。

## 理由

1. 工程第一天就能跑，玩法与美术解耦；
2. 替换素材只改素材与 manifest，一行代码不动；
3. `?debug=assets` 可一眼看全 41 个 key 与尺寸，美术照单生产。

## 后果

- 正面：不阻塞、可替换、风格基调统一（16 色板）。
- 负面：占位图不能当最终美术；已在 `待办事项.md` 登记美术替换风险。
