# ADR-006：卡牌只做「改造卡」类型

- **日期**：2026-10-24
- **状态**：已接受
- **决策人**：P1

## 背景

提案里有改造卡 / 技能卡 / 被动卡三类，但 MVP 只给 10 张卡、1 个角色、5–10 分钟流程。

## 可选方案

- 方案 A：三类都做（技能槽 + 被动槽，UI 与数值工作量大）
- 方案 B：MVP 只做改造卡，`CardType` 预留 `skill` / `passive` 字段
- 方案 C：完全不做卡牌类型字段

## 决策

选 B。`CardType = 'modifier'`，数据结构保留扩展位；10 张卡全部为改造卡，靠 tags 覆盖 4 条流派。

## 理由

1. 核心卖点是「卡牌改造武器行为」，改造卡就够证明；
2. 技能/被动卡会引入主动技能帧、冷却 UI、被动结算等额外系统；
3. 预留字段让下一版无需迁移数据。

## 后果

- 正面：范围可控，M3 能按期验收。
- 负面：卡牌构筑深度有限；下一版需补技能/被动卡与对应 UI。
