# ADR-010 三存档槽 / 关卡进度：模块增量 + 独立存储键

- 日期：2026-10-25
- 状态：**已采纳**（R2/R3/R4/R5 落地）
- 相关：`web/src/core/profile-contracts.ts`、`web/src/core/stage-contracts.ts`、`web/src/systems/SaveSlotStore.ts`、`web/src/systems/StageService.ts`、`web/src/data/stages.json`

## 背景

蓝图要求：三个互相独立的存档槽、存档内容扩展（关卡进度/胜败/最后游玩/出战配置）、导出导入、
关卡循环与难度递增、历史关卡回放。而 `contracts.ts` 冻结（`SaveData` 只有 forge/stats/seen/settings + 教程字段），
`IRunService` 也没有「关卡」概念。

## 决策

### 1. 存档字段：模块增量（module augmentation）

`core/profile-contracts.ts` 里 `declare module './contracts' { interface SaveData { … } }` 增加**可选**字段：

```ts
slot? / createdAt? / lastPlayedAt? / progress? / loadout? / guideSeen?
```

- 纯加法：旧存档缺字段时由 `sanitizeSave` / `readProgress` / `readLoadout` 补默认值；
- 不升 `CONTRACTS_VERSION`，不碰 `contracts.ts` 一个字节；
- 存取小工具放 `systems/TutorialProgress.ts`（教程）与 `systems/SaveSlotStore.ts`（槽位）。

### 2. 三存档槽：分开的 localStorage key

- `aaa1024.save.slot1/2/3` + `aaa1024.activeSlot`；
- `SaveSystem` 保留「当前激活存档」的内存副本，`adoptSlot(i)` 切换并落盘；
- 未选槽位（调试 `?scene=game`）继续用旧 key `aaa1024_save_v1`，保证既有验收脚本与老存档可用；
- 首次启动若三槽皆空且有旧存档 → 自动迁移到槽位 1。

### 3. 关卡进度：运行态放 `game.registry`

- `StageService.beginStageRun()` 把 `{stage, replay, scaling, rewardMul}` 写进 `game.registry`；
- 好处：`Enemy`（缩放数值）、`ResultScene`（展示/折算）都能跨场景读到，不需要改契约的服务表；
- `GameScene` 通关/失败时用 `recordStageClear / recordStageLoss` 写存档，回放不吃主线进度。

### 4. 难度曲线与回放倍率：独立 JSON

`data/stages.json` 存放全部系数（hp/damage/count/speed + challenge 段 + `replayRewardMul`），
代码只套公式（`computeStageScaling`），并通过 `data:validate` 校验（正数、上限、模板占位符）。

## 代价

- `EventMap` 之外的「存档字段」也变成了增量：读代码时要同时看 `profile-contracts.ts`；
- 三套存档路径（槽位 / 旧 key / 未选槽）需要小心：所有读取都走 `readSlot` + `sanitizeSave` 兜底；
- 运行态在全局 registry 里，理论上可被其它场景读；已用 `getStageRun(scene)` 统一入口 + 只读返回约束。

## 备选方案（未采纳）

| 方案 | 未采纳原因 |
|---|---|
| 直接改 `contracts.ts` 加 `progress` 字段并升 v2 | 违反冻结规则，会让历史交付文档的契约版本失效 |
| 三槽塞进一个 key 的数组 | 单槽写坏会拖累全部存档；导出/导入也无法按槽位独立 |
| 难度倍率写死在代码 | 违反「数值进 JSON」铁律，策划无法调参 |
